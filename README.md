# Technical Interview Prep

This repository is a structured interview prep knowledge base for software engineering interviews, especially:
- backend roles
- full-stack roles
- mid-to-senior engineer interviews
- solutions engineer style interviews

It is designed to help you build:
- coding interview strength
- system design fundamentals
- backend and API knowledge
- networking and security understanding
- language/framework-specific backend depth

The goal is not just to collect notes.
The goal is to make you able to:
- explain concepts clearly
- solve problems under pressure
- talk through tradeoffs
- sound strong in real interviews

---

## How To Use This Repo

The best way to use this repo is:

1. start with the study plan
2. use the concept guides to build understanding
3. practice coding problems alongside the DSA guide
4. review system design, networking, and security together
5. speak answers out loud instead of only reading silently

For each topic, try to reach this standard:
- you can explain the concept simply
- you can give a concrete example
- you can describe tradeoffs
- you can apply it in a coding or system design scenario

If you can only recognize a concept when reading it, but cannot explain it from memory, you are not done with that topic yet.

## How To Study Each Guide

A good pattern for each guide:

1. read one section
2. rewrite the idea in your own words
3. explain it out loud without looking
4. build or solve something small related to it
5. revisit it later for spaced repetition

For coding topics:
- write code from memory
- test edge cases
- time yourself sometimes

For system design topics:
- draw the architecture
- explain the request flow
- talk through bottlenecks and tradeoffs

For security topics:
- identify the risk
- explain the mitigation
- explain common mistakes

---

## What “Interview Ready” Looks Like

You are much closer to ready when you can do these without notes:

- explain HTTP vs HTTPS clearly
- explain auth vs authorization clearly
- implement common coding patterns from memory
- describe caching tradeoffs
- explain replication vs sharding
- discuss REST API design with meaningful status codes
- explain what happens when you type a URL
- talk through a simple scalable API design
- explain one language/framework track in detail if the role needs it

Reading alone is not enough.
The real test is whether you can produce the explanation yourself.
